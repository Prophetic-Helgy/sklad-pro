# Техническое описание существующего решения «Склад ПРО 7.1»

> Источник: `E:\БД для Кворк\уже выложены на кворк\Склад Про 7.1\Склад ПРО 7.1.xlsm` (307 КБ)
> Дата анализа: 2026-08-21
> Тип: **VBA-приложение** (макросы + UserForm) поверх Excel-таблиц. Рабочая копия — чистый шаблон (без данных).

---

## 1. Архитектура файла

Приложение устроено так:
- **Листы = слой данных и отчётов** — каждая сущность — именованная Excel-таблица (ListObject) со структурированными ссылками.
- **VBA = слой UI и бизнес-логики** — 10 UserForm + 14 модулей (222 процедуры). Кнопки на листах — AutoShape-фигуры с `OnAction`.
- Все листы и сама книга **защищены паролями** (пароли зашиты в VBA).

## 2. Модель данных (текущая)

### 2.1. Номенклатура (товары) — таблица `Nom`

| Колонка | Тип | Значение |
|---|---|---|
| № | формула | порядковый номер строки |
| **Наименование** | текст | **первичный ключ** (все VLOOKUP ведут по нему) |
| Артикул | текст | необязательный, **уникальность не контролируется** |
| Категория | текст | свободная |
| Ед. изм | текст | свободная |
| Кол-во (нач) | число | начальный остаток |
| Поставщик | текст (список из `Postavshiki`) | поставщик по умолчанию |
| Примечание | текст | |
| Приход (з) / Расход (з) / Списание (з) | число | дополнительные (вручную) объёмы |
| Приход (с) / Расход (с) / Списание (с) | формула | `=Приход + Приход (з)` и т.п. |
| Приход / Расход / Списание | формула | `SUMIFS` из соответствующего реестра по Наименованию |

> **Ключевая особенность:** товар идентифицируется **текстом «Наименование»**, штрихкода нет, артикул не обязателен и не уникален.

### 2.2. Склад (остатки) — таблица `Sclad`

Зеркалирует номенклатуру (наименование — колонка выбора), формулы:

```
Кол-во (нач)   = Nom.Кол-во (нач)
Остаток (факт) = Sclad.Кол-во (нач) + Nom.Приход (с) − Nom.Расход (с) − Nom.Списание (с)
```

Отдельная сущность «склад/место хранения» **не существует** — это единственная глобальная книга остатков. Есть колонка «Поставщик» (по умолчанию).

### 2.3. Поставщики — таблица `Postavshiki`

Полное наименование (ключ), Сокращенное наименование, Юридический адрес, Почтовый адрес, Тел/факс, E-Mail, ИНН, ОГРН/ОГРНИП, Примечание. Роль «покупатель» отдельной сущностью не выделена — в расходе используется «Получил».

### 2.4. Документы

**Приход** (`Prihod`): шапка — Поставщик, Накладная, Дата (`=СЕГОДНЯ()`); позиции: №, Дата, **Наименование** (ввод через форму поиска), Артикул*, Категория*, Кол-во, Ед. изм*, Поставщик*, Накладная*, Комментарий, Выбор (служебный флаг `a`). (* — автозаполнение VLOOKUP из номенклатуры/шапки.)

**Расход** (`Rashod`): шапка — **Отпустил** (сотрудник), **Получил** (покупатель/получатель), Дата; позиции те же, но Поставщик/Накладная заменяются на Отпустил*/Получил*.

**Списание** (`Spis`): шапка — Поставщик, Накладная (№, дата), Дата; позиции: …, **Причина списания**.

### 2.5. Реестры (журналы) — «проведённые» данные

| Таблица | Колонки |
|---|---|
| `ReestrPrihod` | Дата, Наименование, Артикул, Категория, Кол-во, Ед. изм, Поставщик, Накладная, Комментарий |
| `ReestrRashod` | Дата, Наименование, Артикул, Категория, Кол-во, Ед. изм, Отпустил, Получил, Накладная, Комментарий |
| `ReestrSpis` | Дата, Наименование, Артикул, Категория, Кол-во, Ед. изм, Поставщик, Накладная (№, дата), Причина списания |

Реестры — **единственный источник фактов**, по которым считаются остатки (SUMIFS из номенклатуры) и отчёты.

### 2.6. Сотрудники / предприятие — таблица `Sotrud`, лист `Админ`

- Карточка предприятия: полное/сокращённое наименование, юр. и почт. адреса, телефон/факс, E-mail, ИНН/КПП, ОГРН, руководитель, банковские реквизиты (банк, БИК, р/с, к/с).
- Сотрудники: Ф.И.О., Должность, **Логин, Пароль** (открытым текстом в ячейках).
- Кнопка «Включить авторизацию» (флаг в `Warning!D6`).

### 2.7. Архивы — 8 таблиц `Arhiv*`

«Архив накладных» (№, Дата), «Архив отчётов» (Приход/Расход/Возврат/Списание), «Архив реестров» (Приход/Расход/Возврат/Списание). Колонка «Возврат» зарезервирована, но функционала возврата в VBA **нет**.

### 2.8. Накладная (печать)

Очень скрытый лист, заполняется из документа «Расход»: «Расходная накладная № {год} от {дата} г.», «От кого: {карточка предприятия + ИНН}», «Кому: {Получил}», таблица позиций, «Всего наименований: N», места подписей. Используется для печати; помечается в «Архив накладных».

## 3. Бизнес-процессы (как работает)

### 3.1. Запуск
`Workbook_Open` → защита всех листов → заставка → если включена авторизация: форма логина (логин из списка `Sotrud`, пароль сверяется с ячейками). Логин пишется в `Warning!D8`; **только `admin`** видит листы «Админ» и «Архивы». При закрытии листы скрываются, файл сохраняется.

### 3.2. Ввод документа (на примере «Приход»)
1. Кнопка «Новый приход» открывает форму (включаются поля и таблица позиций).
2. Заполняются шапка (Поставщик — из формы выбора/ввода, Накладная, Дата — календарём) и позиции: товар ищется в номенклатуре (поиск по началу/содержанию наименования), указывается Кол-во и Комментарий.
3. «Добавить» — строка в форму, «Удалить» — удаление выбранных.
4. **«Записать»** → подтверждение → выбранные строки **копируются значениями** в `ReestrPrihod` (вставка строк), реестр сортируется по дате, пустые строки удаляются, форма скрывается. Остатки в «Складе» пересчитываются формулами автоматически.
5. «Очистить» — сброс формы.

«Расход» и «Списание» — аналогично; у «Расхода» дополнительно кнопка создания/печати накладной.

### 3.3. Остатки
Считаются **только формулами**, на лету: `Остаток (факт) = Кол-во (нач) + Σприход − Σрасход − Σсписание`. Отдельной операции «проведение» нет — запись в реестр = проведение.

### 3.4. Отчёты
«Отчет по приходу/расходу/списанию»: фильтры — Поставщик (Сотрудник у расхода) + период «с…по» (календарь); строки — позиции с `SUMIFS(Кол-во, Наименование, Период [, Поставщик])`, колонка «Чек» (пометка для печати), «Всего позиций» через `AGGREGATE`. Отчёт и реестр можно **архивировать** (копия в таблицы `Arhiv*`).

### 3.5. Защита
Пароли листов (UserInterfaceOnly), запрет вставки/вырезания/перетаскивания, скрытые сервисные листы, формулы сокрыты. Это **псевдозащита**: пароли и весь код находятся внутри файла.

## 5. Болевые точки Excel-решения

| # | Проблема | Последствия |
|---|---|---|
| 1 | Один файл = одна база, один пользователь | Нет работы в локальной сети, блокировка файла, конфликт «кто открыл» |
| 2 | Товар = текст «Наименование», без кода/штрихкода; артикул не уникален | Опечатка = новый «товар»; невозможно сканирование; двойники |
| 3 | Нет истории изменений и аудита | Неизвестно, кто и когда поправил данные |
| 4 | Нет контроля отрицательных остатков | Расход можно записать больше, чем есть |
| 5 | Нет инвентаризации | Реальные и книжные остатки не сличаются; «Кол-во (нач)» правится вручную |
| 6 | Одна глобальная «книга», нет сущности склад/зона | Невозможен перенос между точками хранения |
| 7 | Нет денег: себестоимости, цен, сумм | Отчёты только в штуках; нет оборотов и ABC-анализа |
| 8 | Нет резервирования товара | Под заказ может уйти чужой остаток |
| 9 | «Запись в реестр» необратима без VBA-прав | Корректировка/возврат документа — вручную в защищённом листе |
| 10 | Нет автоматического резервного копирования | Риск потерять данные вместе с файлом |
| 11 | Пароли листов открыты в VBA, пароль сотрудников — открытый текст | «Защита» декоративна |
| 12 | SUMIFS по всему реестру на каждую строку | Замедление по мере роста данных |
| 13 | Нет поиска/фильтра на «Складе», нет истории движения по товару | Медленно искать, не видно, почему остаток такой |
| 14 | Обрывки: «Возврат» в архивах без функционала; битая формула `#REF!` в `Склад!F3` | Нестабильность шаблона |
| 15 | Отчёт = «распечатать копию» | Нет экспорта Excel/PDF, нет аналитики по периодам «остатки на дату» |

## 6. Что переносить в новое приложение (данные)

1. `Postavshiki` — все строки (9 полей).
2. `Nom` — все строки (наименование, артикул, категория, ед. изм, кол-во нач, поставщик, примечание; ручные «(з)»-объёмы).
3. `ReestrPrihod`, `ReestrRashod`, `ReestrSpis` — все строки (история фактов).
4. `Sotrud` — сотрудники (логин, пароль, должность).
5. Карточка предприятия (14 полей).
6. `Arhiv*` — списки архивных копий (сохранить как справочную).
7. Остаток «Остаток (факт)» — не переносится как факт: восстанавлится автоматически из начальных остатков + реестров.

Перенос проверяется контрольными суммами: Σ реестров по товару = значения формул в старом файле.
